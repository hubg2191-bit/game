# Тестирование для другого чата — testing

## Досинк-детект
- Хеш sim-состояния каждые 5 сек (`hash(x,hp,gold)`), клиент шлет свой хеш. Расхождение 3 раза подряд — `desync` + full-snapshot + лог.
- `simVersion` в каждом снапшоте. Не совпал — кик с подсказкой обновиться.

## Боты
- `bot_easy`: фармит, не рейдит. `bot_mid`: держит фланг. `bot_hard`: фокусит осадные (для теста). Бот = тот же sim + скрипт команд, без читов (тот же туман).

## Нагрузочные
- 1 BattleRoom 4 игрока x 12 отрядов = 48 отрядов: tick <30мс, снапшот <100кб, 10 Hz держится.
- LifeRoom 60 онлайна: чанки <50кб/сек на игрока, autosave <500мс.
- Лаг-тест: 250мс + 5% потерь — играбельно, приказы не теряются (ретрай seq).

## Верификация на клиенте (1.0, до сервера)
- `hashState(state)` в `src/game/sim.js`: FNV-хеш тика/позиций/HP/ресурсов/счёта. Проверка: две параллельные игры, сид 7, 600 тиков — хеши равны (`a2bd1631`).
- Найден и починен десинк-баг: глобальный счётчик id сущностей делился между играми в одном процессе. Счётчик перенесён в `state.nextId` — критично для комнат сервера и реплеев.
- Тик сима ~0.00мс при ~23 отрядах (лимит 30мс с запасом). Замер 48 отрядов — на сервере.
- Клиентский APM-лимит 10/сек уже режет спам в UI; серверная валидация — в `server/`.
